# 表格规则和字段对应关系

依据：[原始需求说明](https://zepp.feishu.cn/wiki/MKDTwtkY4iAk3wkjGP1cGmNTnab)与[原始测试表](https://zepp.feishu.cn/wiki/RfFHwbgnDifAmVkNKnLcPvaonYd)。以下列名按已验证的模板整理；换项目或换表时，要重新核对表名、列名和项目规则。

## 哪些行要处理

| 工作表 | 处理方式 |
| --- | --- |
| 项目人员信息 | 查负责人 Jira 账号，以及阶段对应的版本；同名人员不能随意择一 |
| Epic | 按筛选创建；已有编号先核对，结果写入“Epic Link(导入后填写)” |
| 适配任务 | 处理筛选范围内且“是否适用本项目=是”的行；结果写入“Key(导入后填写)” |
| 适配子任务 | 处理筛选范围内、上级为本项目真实 Task 的行；NG、空编号和错误值单独记录 |
| 新功能开发任务 | 用户明确要求时再处理；AAA/BBB 等只是示例文字 |
| 导入到Jira | 读取说明和字段配置附件，为本项目生成配置 |

先按表格筛选选行，再核对上级编号。手动隐藏行和个人筛选视图也要确认范围。

**ShutOff** 是关闭不用模块的检查任务，例如关闭配置开关、释放引脚和总线。是否导入由本次需求和筛选决定；按表格指定的上级任务建单，不要只看任务名字，就自行调整它属于哪个任务。

四张参考页保持原样：版本说明、使用说明、任务分解模板、仅用于测试各种公式。

## CSV 列对应哪个 Jira 字段

| 表格列 | Jira 字段 |
| --- | --- |
| Summary | `summary` |
| Issue Type | `issuetype` |
| Assignee（负责人） | `assignee` |
| Reporter（报告人） | `reporter` |
| Fix Version/s（目标版本） | `fixVersions` |
| Severity（严重程度） | `customfield_10401` |
| 启动时间 | `customfield_10702` |
| 到期日 | `duedate` |
| Epic Name | `customfield_10103`，用于 Epic |
| Epic Link | `customfield_10101`，用于关联 Epic |
| 详细描述 | `description` |
| 父级ID | CSV 导入器用 `subtask-parent-id`；REST 接口用 `parent.key` |

Epic、适配任务、子任务分别使用对应的配置附件。新功能配置还含 Epic Name，使用 REST 创建 Task 时要核对是否允许填写。

原附件没有导入 Component/s 和人小时估算。预览保留这些数据供查看；用户要求同步时，再核对组件名称和工时设置。人小时不能直接当成人天。

## 字段怎么检查

- 从目标项目的创建规则（`createmeta`）确认必填项、字段类型和可选值；不要固定使用某个项目的值。
- 负责人账号要存在且能被该项目指派，版本必须属于该项目。缺少信息时指出问题，不改派给当前用户凑数。
- 访问级别、组织归属等字段不猜填；需要默认值时，只依赖已核实的服务端默认值。
- Reporter 需要相应权限。执行脚本使用实际创建者；用户明确要求其他报告人时，先解决权限限制。
- 已有任务按项目、类型、标题、负责人和上级关系核对。同一上级下找到多个同名任务时，停止自动选择。

## 公式、编号和日期

- 用 `FormattedValue` 读取公式结果。不要把 `VLOOKUP(...)` 等公式文本当作账号或编号，也不要在本地用 `eval` 运行公式。
- 先创建上一层、写回实际编号，再读取下一层。还没有编号的关系只能作为待完成步骤，不能直接导入。
- `#REF!`、`#N/A`、版本值 `0` 都需要检查。列出行号和原因，不把错误值传给 Jira。
- Epic 空编号会让 SUMIF 暂时汇总错误；写回编号后再同步重算日期。`TODAY()` 的结果也要重新读取，不固定使用旧日期。
- CSV 日期用 `yyyy/MM/dd`，REST 日期用 `yyyy-MM-dd`。每个 CSV 最多 250 条数据行，不含表头，编码为 UTF-8。

每次执行都记录原表、行号、批次和 Jira 编号。创建成功后及时保存结果；重复运行前先查日志和 Jira。
